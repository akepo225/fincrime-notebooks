# Honest Metrics Notebook

Companion notebook for the article
[The Honest Metrics of Fraud Detection: Precision, Recall, and the Investigator Capacity Constraint](https://yvesakepo.substack.com/p/the-honest-metrics-of-fraud-detection).

- **Everything is synthetic.** No real bank, client, or transaction data. A seeded generator
  (seed 42) creates a synthetic bank: 30 days × 200,000 transactions at 1-in-500 fraud
  prevalence, scored by a synthetic model with ROC-AUC ≈ 0.968.
- **Every figure and every number quoted in the article is regenerated by this script**,
  deterministically: the capacity table, the capacity curve, the queue-policy comparison, and
  the 90-day backlog simulation.
- License: MIT (see the repository root).

## Run it

From this folder:

```bash
uv run --no-project --with numpy --with pandas --with matplotlib python honest_metrics.py
```

(Or any Python 3.11+ with numpy, pandas, and matplotlib: `python honest_metrics.py`.)

The script prints the summary numbers and writes the four figures to `figures/`, plus
`capacity_curve.csv` with the full capacity sweep. Running it twice produces byte-identical
output.

## What to look at

- `precision@N` and `value-recovered@N` at the alert budgets quoted in the article
  (500 / 1,000 / 2,000 / 5,000 per day).
- The EV calculation behind "the value-maximizing budget is more than five times what the team
  can work" (triage cost £6/alert).
- The amount-aware queue policy (score × amount) that lifted value recovered from 38.5% to 87.5%
  at the same 2,000-alert budget.
- The queue simulation: final backlogs 0 / 152 / 876 / 9,001 at utilization 0.70 / 0.85 / 0.95 /
  1.05.

Swap in your own scores and amounts (on your own infrastructure, never real customer data) and
the same script produces your shop's capacity curve.
